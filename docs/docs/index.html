Can Historical Search Signals Help Prioritize Content Refresh Review?

Author: Zubair Tariq
Lane: Content Refresh Opportunity Scoring
Date: August 2026

Abstract

This project asks whether historical search-performance signals can help prioritize which published content pages deserve human review for possible refresh work.

Using the FlyRank ML Internship dataset, I analyzed 85,967 eligible pages and evaluated models on a grouped client holdout of 4,247 pages.

I compared a transparent staleness-and-visibility baseline with Logistic Regression and Random Forest using five pre-decision search features.

Logistic Regression produced the strongest fresh result, reaching 55% precision@20 compared with 20% for the rule baseline, while overall ROC-AUC remained modest at 0.5537.

The final output is a human-review action queue designed to prioritize editorial investigation rather than automate content changes.

Introduction / Problem statement

The project asks whether historical search-performance signals can help prioritize which published content pages deserve human review for possible refresh work.

The unit of analysis is a published content page. The system produces model scores and a ranked queue that helps an editor decide which pages to inspect first.

The intended action is not automatic rewriting or publishing. A human reviewer decides whether a page should be reviewed for freshness, checked for weak click capture, monitored, or held.

A wrong high-priority call can waste editorial effort or encourage unnecessary changes. A wrong low-priority call can delay review of a page that may deserve attention.

Machine learning helps by ranking a large content portfolio that would be difficult to review manually, while keeping the final decision with a human.

Data

This project uses pseudonymized content-performance data from the FlyRank ML Internship dataset, warehouse build 20260703.

The analysis uses:

  • fact_content_daily_performance
  • dim_content

Historical search signals were measured from March 1–21, 2026. The later March 22–31, 2026 window was used only to define the evaluation outcome.

The five model features were:

  • past_impressions
  • past_clicks
  • past_ctr
  • past_avg_position
  • gsc_observed_days

The final eligible population required at least 7 observed GSC days in the feature window, at least 5 observed days in the outcome window, at least 100 historical impressions, and published non-deleted content.

Pseudonymous IDs were used only for grouping, joins, and evaluation. Label-derived fields, future-window information, client names, page URLs, private queries, and credentials were excluded from model features and public outputs.

Methodology

The task is treated as a ranking problem around a binary future_decline proxy.

A page is labeled positive when its average daily impressions during March 22–31, 2026 are less than 80% of its average daily impressions during March 1–21, 2026.

Three approaches were compared:

  1. Transparent staleness + visibility rule baseline
  2. Logistic Regression
  3. Random Forest

Validation used a grouped holdout by client_hash_id with a fixed random seed of 42. This prevents pages from the same client appearing in both training and test data.

Logistic Regression produced the strongest fresh benchmark result, while Random Forest was retained as the scoring model used by the Week 7 action playbook.

Results

The deterministic split contained 81,720 training rows and 4,247 held-out test rows. The test set contained 8 clients, with zero client overlap, and a positive base rate of 41.96%.

Method Precision@10 Precision@20 ROC-AUC
Rule baseline 10% 20% 0.4760
Logistic Regression 40% 55% 0.5537
Random Forest 40% 50% 0.5529

Takeaway: both learned models improved top-of-queue precision over the rule baseline, but overall discrimination remained modest.

Logistic Regression produced the strongest fresh result. It matched Random Forest at precision@10, exceeded it at precision@20, and had a slightly higher ROC-AUC.

The results support using the learned ranking as a decision-support signal, but do not justify automatic content decisions.

Limitations & honest framing

This analysis is observational and predictive. It does not show that refreshing a page causes an improvement in search performance.

The future_decline target is a practical proxy and does not represent every form of content deterioration.

The held-out test population contains only eight clients, so performance may differ for substantially different client or content distributions.

The evaluation also applies only to pages with sufficient observed GSC coverage and at least 100 historical impressions.

Overall ROC-AUC remained close to 0.55. The model should therefore be used as a prioritization aid rather than an automatic decision system.

Ranked recommendations

The final held-out queue contains 4,247 pages:

  • 276 REVIEW_FOR_REFRESH
  • 538 CHECK_CTR
  • 1,608 MONITOR
  • 1,825 HOLD

Takeaway: most pages are monitored or held, reflecting a deliberately conservative review policy.

The recommended workflow is:

  1. Review REVIEW_FOR_REFRESH pages first because they combine higher measured risk with enough existing visibility to justify editorial attention.
  2. For CHECK_CTR, inspect title, snippet, SERP context, and search-intent alignment before considering broader changes.
  3. For MONITOR, wait for another measurement window unless other evidence suggests urgent review.
  4. For HOLD, take no immediate action unless new evidence appears.

The system should not automatically rewrite or publish content, delete pages, change redirects or canonicals, modify metadata, or make spending decisions from model scores alone.
